## Overview

**Creative North Star: "安靜的刊物"**

像一份沉穩的文藝刊物：象牙白的紙、細細的框線、區塊標題底下一道雙線、品牌字標的宋體帶出書卷氣，再加上 Apple 式的層次與質感。資訊清楚、留白有節制。動態強度提高（全站基準 6、敘事段落 9）後不再是「慢而克制」，但仍要每個動態都有理由。重點內容（宣傳影片、最新消息、族語認證最新公告）在第一屏同時看得到，不逼人一直往下拉。

這個風格不是靠裝飾取勝，而是靠排版、字型、層次與少量一致的規則。不使用硬偏移陰影、貼紙、星芒、膠帶、旋轉、五色棋盤格。層次來自表面色階、柔和多層陰影（高度 0 到 4，已定案）與毛玻璃材質（目前套用在內頁導覽列；其他位置隨各頁改版決定），不來自裝飾。

**使用者的版面回饋（已實作於風格稿）：** 東西畫太大會逼人下拉；報頭縮成一條（舊風格稿回饋，2026-11-06 已由「報頭併入第一屏當 hero」取代）；設定類控制收進面板；導覽列沿用現有網站選單，不自創項目。

**Key Characteristics:**
- 象牙白紙感底，深石板色文字，不用純白底黑字。
- 1.5px 細框（小元件與小型、列表卡）、8／12／20／28px 圓角階層、區塊標題下雙線（雙線是否保留待確認）。
- 沒有硬偏移陰影；大卡用柔和多層陰影，小元件用細框（高度 0 到 4 已定案）。
- 全站 Noto Sans TC 無襯線；只有品牌字標保留 Noto Serif TC。
- 動態：全站基準強度 6，捲動敘事段落強度 9（使用者看過樣片後選定），全部尊重減少動態設定。
- 淺色與深色兩套，預設淺色，提供淺色、深色、跟隨裝置三態。

## Colors

三主色加紙感中性色。**一頁只有一個強調色（銅褐系）**，橄欖卡其做次要標記，石板灰做承載區塊。

### 三主色（使用者指定）
- **銅褐** (#98694C)：品牌主色。用於大面積色塊、細框強調、大字（18.66px 以上粗體或 24px 以上）、圖示。
- **橄欖卡其** (#86754D)：次要標記色、分類標籤的底色邊框。
- **石板灰** (#41464B)：承載區塊底色（例如族語認證最新公告面板）、導覽與報頭色塊。

### 中性與輔助色（我加的，D1 已同意）
**使用規則（D1 結論）：** 象牙白維持 #FFF9ED，不改冷白（冷白會讓銅褐與橄欖變灰）；不再新增第二個品牌強調色；淺銅只限石板灰區塊上的小字，不擴張成第四主色；狀態色（成功、警告、危險、資訊）只能功能性使用，不進裝飾與大面積背景，危險色維持莓紅、不用銅褐代替，狀態一律文字加圖示；石板灰區塊只限最新消息與認證公告，用 `.yy-on-dark` 包起來，不擴散成其他深色段落。誠實備註：#FFF9ED 偏奶油色，是整組裡最接近「暖米色加黃銅」套版的一個，文字用冷調深石板、主色由使用者指定，所以成立。
- **象牙白** (#FFF9ED)：頁面底色。
- **深石板** (#292D31)：文字與細框。
- **深銅** (#7E5239)：連結、小字強調、主要按鈕底色。
- **深橄欖** (#6F6040)：小字標記底色。
- **淺銅** (#C9976F)：只放在深石板 (#292D31) 底上的點綴。石板灰 (#41464B) 底上改用 #D7A98B（對比 4.51），語意 token 是 `--yy-calm-block-accent`。
- **白** (#FFFFFF)：卡片與輸入框底色。
- **分隔線淺色** (#E9E2D2)：列表內的細分隔。
- **三主色淡階**（2026-11-06 批准新增）：使用者只批准「允許新增三主色的淡階」。混色方式（暫定混入象牙白）、用途（暫定只當分區底色，不新增色相、不當強調色）與色值，都待階段 1 步驟 1-5 提案後確認，且須實測對比。

### 狀態色
成功 (#2F6F4B 字／#E3F0E8 底)、需注意 (#7D5B0E／#F6ECD3)、錯誤 (#8A3A4E／#F5E1E6)、資訊底 (#EFE6DA)。深色模式各有對應的亮色字與深色底（見 frontmatter 與下表）。

### 深色模式（預設淺色；可手動切換，或選擇跟隨裝置）
底 #24282C、卡片 #2E3338、文字 #F2EEE3、次要文字 #D3CEC1、框線 #7D868E（原 #6B747C 對卡片底只有 2.68，未達 3:1，已調亮）、銅褐 #C99372、深銅 #D7A98B、橄欖 #B3A06A。狀態色與提示底色值見 frontmatter。

實作在 `frontend/static/css/default/theme-v2.css` 的 `--yy-calm-*`（23 個語意 token，舊 token 原封不動）。`<html data-theme="system">` 才跟隨裝置，`data-theme="dark"` 手動深色；沒有屬性或其他值都是淺色，切換程式要拒絕未知值。S2-1 起共用按鈕、標籤、晶片、頁籤已使用這些 token，而多數頁面底色仍是舊象牙色，所以跟隨裝置必須明確選擇才生效，深色系統的使用者畫面不變。啟用深色前置條件：兩個深色區塊加 `color-scheme: dark`，`index.html` 的 color-scheme meta 改為 `light dark`。深色的提示底與卡片底幾乎同色（約 1.1:1），提示框必須加 1px 框線。主題切換不做顏色過渡。

### Named Rules
**The 主色不直接做小字 Rule.** 三個主色的原色在象牙白上做小字或普通大小的按鈕文字，對比不足（銅褐 4.49、橄欖 4.29）。小字、連結、按鈕底色一律改用深一階的深銅或深橄欖；原色保留給色塊、大字，以及對相鄰顏色達 3:1 的必要邊框與功能圖示（WCAG 1.4.11；純裝飾圖示不受限）。這不是質疑主色，是讓主色在正確的位置發揮。

**The 狀態不靠顏色單獨表達 Rule.** 答對、答錯、已選須同時有文字或圖示（WCAG 2.2 AA）。

**The 一頁一強調色 Rule.** 銅褐系是唯一的強調色；橄欖只當次要標記；不再引入第三個強調色。

**五個族語識別色（舊系統遺留，待決定）：** 舊系統每個族語有一個識別色（泰雅赭紅、阿美靛藍、噶瑪蘭湖青、排灣赤金、布農森綠），與新的三主色風格衝突。改版計畫的方向是**只作為小標記，不做大面積色塊**；是否保留、改色或移除，在 S1 與 S8 逐頁處理時與使用者決定，這裡不先下結論。

### 族語色與選取狀態（P1-2，2026-11-17）
族語色只當辨識記號：`TribePill` 的 8px 圓點（`.yy-pill__dot`），顏色以 `color-mix` 與表面色混合到約 62%（不支援時退回 62% 不透明度），不用整塊填色、不當文字色。**所有「已選取」狀態共用同一個樣式：** 深銅底、象牙字、加一個勾（`.yy-is-selected`、`.yy-pill.active`），選取後圓點外加象牙色細環，確保不只靠顏色辨識。全站仍只有一個強調色，不再為族語另設第二強調色。

## Typography

**標題與導覽（2026-11-06 批准全站無襯線）:** Noto Sans TC，字重 700 到 900（fallback：PingFang TC、Microsoft JhengHei、sans-serif）。目前程式碼的 `--yy-font-heading` 仍是 Noto Serif TC，階段 1 步驟 1-4 才切換。
**品牌字標:** 「原語」與 YUAN・YU 字標保留 Noto Serif TC，是全站唯一襯線。因此仍要載入宋體，預計只載入字標用到的字（Google Fonts 的 text 參數），可行性於步驟 1-4 確認。
**內文與表單:** Noto Sans TC（fallback：PingFang TC、Microsoft JhengHei、sans-serif）

**為何改無襯線:** 使用者最喜歡 Apple design，2026-11-06 選擇全站無襯線；書卷氣改由品牌字標的宋體、留白與排版節奏承擔。原先「編輯出版類調性所以用宋體」的理由已由使用者的新決定取代。

**載入方式:** 專案規則是用 HTML 的 `<link rel="preconnect">` 加 `<link rel="stylesheet">` 載入 Google Fonts，**不用 CSS `@import`**（效能，使用者的既有規則）。

**族語字母（S1-1 已實測，2026-10-16）:**
- **Noto Sans TC 與 Noto Serif TC 都沒有族語特殊字母。** 用 fontTools 讀完整字型檔的字元對照表，51 個候選字元（官方《原住民族語言書寫系統》113 年修正對照表出現的全部非中日韓字元，含音標，未區分書寫符號與音標；加上專案程式碼實際用到的 ʼ ʻ ʾ ṣ 與組合符號）中，TC 字型只有 11 個。其中 ʼ（U+02BC）、ŋ、ɨ、ʉ、ʔ、ʾ、ṣ、組合下點都沒有，所以**舊系統其實本來就把這些字母丟給使用者的系統字型**，並非「已正確顯示」。
- **補法：** 在 TC 之後接不帶 TC 的 Noto Sans／Noto Serif，51 個字元全部有字形。Google 依 unicode-range 切片，只下載頁面用到的切片。
- **已知缺口（內文堆疊）：** U+0332 組合底線有字形，但 Google 沒有把包含它的切片送給 Noto Sans，實測瀏覽器由備援字型補出底線，位置看起來正常。官方文件提到泰雅語用底線符號區分 ng 與 n、g，但真實字典資料有沒有用到這個字元還不確定。**不能宣稱 51 個字元都由網路字型保障。** 待辦：用字典資料查 U+0332 是否出現；出現時必須在 Windows Chrome、Android Chrome、iOS Safari 驗證 n̲、g̲、ng̲ 的位置、複製與搜尋；只有跨平台出現錯位或方框，才考慮自管子集字型（要承擔授權、版本與快取維運）。不使用 text-decoration 取代（會破壞複製、搜尋與語意）。
- **字型順序有實測依據：** 全站內文必須 `Noto Sans TC` 在前。Chrome 實測 Noto 在前時，中文排版的「⋯」變成低位「...」、全形「・」縮成小圓點、破折號變粗，中文標點全部退化。顯示族語詞彙的元素才使用 `--yy-font-tribal`／`--yy-font-tribal-heading`（Noto 在前，同一個詞不中途換字型），各頁改版時套用。
- **載入方式：** 可變字型區間（400..900、500..900），CSS 約 257KB，舊的逐一列字重約 748KB；專案用到的 650、850 字重現在是真字重（以前會被映射到 700、900），文字寬度與換行可能略有不同，各頁改版時做截圖比對。
- **證據與重新產生：** `frontend/static/css/fontCoverage.fixture.json` 由 `scripts/build_font_coverage_fixture.py` 產生（不要手動改），`fontStack.test.js` 鎖定堆疊順序與涵蓋。字型升級或改網址時重跑腳本。
- **尚未量測：** 頁面層級字型換字（`display=swap`）造成的 CLS，需要 Lighthouse 或實機量測後再決定是否要預載或調整備援字型的度量。

## Elevation & Depth

**沒有硬偏移陰影。**（2026-11-06 批准，步驟 1-3 已實作）層次由表面色階、細框與柔和多層陰影構成：大卡柔影、小元件細框。

高度 token `--yy-elev-0`、`--yy-elev-1`、`--yy-elev-2`、`--yy-elev-3`、`--yy-elev-4`：0 與 1 為 none；2 為 `0 1px 2px` 加 `0 4px 12px`（深石板 5% 與 7%）；3 為 `0 2px 4px` 加 `0 12px 28px -4px`（6% 與 13%）；4 為 `0 4px 8px` 加 `0 24px 48px -8px`（7% 與 22%）。陰影色相取自深石板 rgba(41, 45, 49, …)，不用純黑。舊 `--yy-shadow-sm／md／lg／overlay` 已刪除。

**深色模式：** `--yy-elev-2` 到 `-4` 改為不畫陰影（`0 0 0 0 transparent`），1px 內描邊獨立成 `--yy-edge-2／3／4`（淺色為空，深色為 `inset 0 0 0 1px` 象牙色 6%、9%、12%），「越高越亮」靠 `--yy-calm-layer-0` 到 `-3` 的表面色階。**只給沒有自己 border 的元件加 edge**（用法 `box-shadow: var(--yy-elev-4), var(--yy-edge-4)`，目前只有側欄），有 border 的元件只用 elev，否則深色下會疊成雙框。

**表面層級與淡階（步驟 1-5）：** `--yy-calm-layer-0` 頁底、`-1` 卡片、`-2` 浮起卡、`-3` 浮層；淺色後三層同為白、靠陰影分層，深色越高越亮。三主色淡階 `--yy-calm-tint-copper-1`、`-copper-2`、`-copper-3`（olive、slate 同）（5%、10%、15% 混象牙白，使用者選 C 組；深色混 #24282C），**只當分區底色**，內文、次要文字、強調連結放在每一階上皆 4.5:1（`calmPalette.test.js` 檢查）。

**毛玻璃（步驟 1-6）：** `--yy-glass-blur`（18px）、`-saturate`（180%）、`-bg`、`-bg-solid`、`-border`、`-halo`。透過 `.yy-glass` 使用；一律有 `prefers-reduced-transparency` 與不支援 `backdrop-filter` 的純色降級；玻璃面上的焦點環加淺色光暈。**導覽列的模糊放在 `::before`，不放在 `.navbar` 本身**，否則內部 `position: fixed` 的側欄與遮罩會改以導覽列為定位基準。雜誌版導覽（首頁）尚未套用。

**景深光與頂緣高光（P1-1，2026-11-17）：** `--yy-ambient` 是頁面頂部一層很淡的銅色放射光（`.yy-page` 的最上層背景，高度取 70svh 與 560px 的較小值，底下仍是不透明的 `--yy-calm-bg`，所以不影響文字對比）。`--yy-lit` 是卡片頂緣 1px 的內側白光，只在淺色有值，深色為空（深色已經用表面色階分層）。用法 `box-shadow: var(--yy-elev-N), var(--yy-lit)`，已套在搜尋結果卡、翻譯卡、故事卡、筆記工具列、登入類頁面的卡片。designGuard 白名單只多放行 `var(--yy-lit)`，其餘手寫陰影仍不允許。

## Motion

（2026-11-06 校正）原本「慢而克制」的定位，隨動態強度提高（基準 6、敘事 9）而放寬。每個動態仍要回答「為什麼動」：階層（引導注意）、回饋（確認使用者操作）、狀態轉換。

### Token
- 曲線：`--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`（進場與回饋）。
- **進場淡入：目前實作 220ms**（`--dur-base`，淡入加上移 8px，一次；逐項進場 420ms），只用於首屏與區段第一次進入視窗，**每次載入只播一次**。2026-11-06 校正：舊文件寫的「約 800ms」從未在 CSS 實作（全部前台 CSS 查無約 800ms 的進場），已刪除。進場節奏隨動態強度新目標，由階段 1 步驟 1-7 的動態樣片決定。
- **互動回饋：150ms 到 220ms**（hover、按壓、展開收合）。
- **hover 輕浮：translateY(-3px)**，只用 transform。
- **按壓：scale(0.97) 到 scale(0.99)**。
- 位移類動畫優先只用 `transform` 與 `opacity`，禁止高頻動畫 layout 屬性（width、height、top、left）；顏色、焦點框、播放進度與展開收合等必要變化可以過渡；不用 `transition: all`。

### 動態強度：基準 6，敘事段落 9（2026-11-06 使用者看過樣片後決定）
原本批准「強度 8 以上」，使用者看過 6、8、9 三段樣片後選定：**全站基準用強度 6**（220ms ease-out、hover 抬起、按壓縮放、進場淡入上移）；**強度 9 只用在捲動敘事段落**（彈簧、捲動連動、View Transitions），且其內容動畫設計要非常精緻精細完整，逐段與使用者定稿後才實作（對應步驟 3-7）。已實作的 token：`--ease-spring`（CSS `linear()`，舊瀏覽器不支援時退回 `--ease-out`）、`--dur-spring` 550ms、`--dur-press` 120ms、`--yy-lift` -3px。按壓縮放已涵蓋導覽項、功能卡、公告與消息列表列、專題卡（`designGuard.test.js` 鎖定每一項有 `:active` 的 transform 規則），其餘各頁的可按卡片隨各頁改版接上。下列規則不因強度提高而放寬：每個動畫先回答「為什麼動」；位移類只動 transform 與 opacity；鍵盤與高頻操作不加動畫；全部尊重減少動態。新增的彈簧（以 CSS `linear()` 模擬，不新增套件）、捲動進場（scroll-driven animation 或 IntersectionObserver）、View Transitions 都要先經樣片確認，`designGuard.test.js` 的動態白名單隨之更新。互動回饋仍維持 150ms 到 220ms。

### 暫停控制（WCAG 2.2.2，與減少動態無關，所有人都適用）
- 自動播放超過 5 秒的內容（跑馬燈、自動輪播）**一律要有可見的暫停控制**，不能只在減少動態時才停。
- 輪播另外在 hover、鍵盤焦點進入、分頁隱藏時暫停；使用者手動暫停後，不可因滑鼠離開而自動重新啟動。
- **風格稿現況缺口：** 風格稿的跑馬燈暫停選項放在導覽列右側的「預覽設定」面板內，正式版必須改成跑馬燈旁的可見控制（列入 S6-1）。

### 減少動態
- `prefers-reduced-motion: reduce` 時：**直接取消進場動畫**（不位移、不淡入，內容立刻 opacity 1）；hover 不位移；跑馬燈靜止；輪播不自動播；影片不自動播放，只顯示封面與播放鈕。
- **內容不得先設為透明再依賴 JS 或動畫恢復**；JS 沒載入或動畫被關閉時，內容必須可見（風格稿用 `.js` class 守門，實作時要沿用）。
- hover 位移放在 `@media (hover: hover) and (pointer: fine)` 內，避免觸控裝置誤觸。
- 鍵盤操作與高頻動作不加動畫。

### 動態語法（S2-2 已完成）
全站只有三種動態，其他一律不加（theme-v2.css「動態語法」註解與 `designGuard.test.js` 鎖定）：
1. **回饋**：按下、hover、焦點的顏色與 transform，150ms（`--dur-fast`）。
2. **狀態**：彈窗與浮層進場 200 到 240ms、退場 160ms；載入佔位、錄音中、等待回覆這類「正在進行」的指示可以循環（白名單）。
3. **進場**：內容出現只淡入並上移 8px，一次，220ms（`--dur-base`）；整頁進場 `.yy-fade-up` 與捲到才進場 `.yy-reveal` 共用 `yy-enter`。`.yy-fade-up` 用 `backwards`，結束後不殘留 transform。

曲線一律 `--ease-out`；位移只用 transform 與 opacity。

**詳情面板的動態與共享元素轉場（P1-3，2026-11-17）：** 詳情浮出的形狀與手感原為「桌機右側面板、手機底部抽屜、進場 220ms、退場 160ms」，是使用者授權我建議的內容；2026-11-18 使用者指出應為置中通知式，桌面已改成置中卡片（見「單詞詳情浮出與查詢頁」），手機底部抽屜不變。手機底部抽屜進場用 `--ease-drawer`（`cubic-bezier(0.32, 0.72, 0, 1)`，iOS 式、不過衝，才不會在底緣露出縫），退場維持 `--ease-out`。**鍵盤開啟不加動畫**：詞卡 click 的 `detail` 為 0 時（鍵盤或程式化觸發，屬經驗判斷）Offcanvas 以 `animation={false}` 開啟。`utils/viewTransition.js` 的 `withSharedTransition`（建立在 `routeTransition.jsx` 的 View Transitions 上，不支援、減少動態、鍵盤觸發、出錯時一律直接更新）已備妥並有測試，但**刻意沒有接到詳情面板**：Bootstrap Offcanvas 自己有位移動畫，詞卡變面板的共享元素轉場會和它互相打架，需要先改成自製面板才合適。

**抽象封面（P1-5，2026-11-17，已量產）：** `AbstractCover` 是遊戲入口卡（四種遊戲各一個排法與色調）與收藏預設圖（`lite` 版）共用的自繪封面，選定 A 色塊疊合並採 Liquid Glass 呈現：三塊玻璃（圓、方、藥丸）疊在低飽和色斑上，上亮下暗的邊緣亮邊、細微色散、隨游標移動的高光與投影；固定比例，不造成版面位移，純裝飾（`aria-hidden`），沒有任何族群圖騰。顏色與玻璃參數全部是 `--yy-cover-*` token（亮暗各一組），陰影收斂成 `--yy-cover-edge`／`--yy-cover-drop` 兩個，designGuard 只放行這兩個。**層次是 2D 分層**（沒有 perspective，所以不用 translateZ）。動態只有進場一次（560ms，每層相隔 90ms，從模糊中成形，色斑約 4 秒落定一次）；**不做常駐漂移**（超過 5 秒的自動動態需要暫停控制，WCAG 2.2.2）。游標光源只在滑鼠、非減少動態時啟用，以 rAF 合併更新。降級：減少透明度與不支援 `backdrop-filter` 為實色玻璃，減少動態為靜態平面。收藏清單用 `lite` 版（無 `backdrop-filter`、無動畫），因為清單可能很長。玻璃模糊在低階手機上的效能尚未實測。

**已刪除：** 逐字進場（CharReveal 元件與測試）、布幕拉開、24px 彈起、按鈕金色脈動與首頁 CTA 光圈、流光字（`.yy-holo-text` 改為靜態的 `.yy-accent-text`）、漂浮光斑與貼紙漂浮、卡片頭部流動色帶、導覽列跑馬燈與菱形光圈。導覽列沒有任何常駐動畫。

**WCAG 2.2.2 備註：** 白名單內的循環動畫（骨架脈動、游標、錄音脈動、轉圈、跳動點）屬載入與進行中指示，視為必要；若日後有超過 5 秒的狀態，旁邊要有文字說明狀態。

## Do's and Don'ts

### Do:
- **Do** 小字、連結、按鈕底色用深銅或深橄欖，原色主色留給色塊、邊框、大字與圖示。
- **Do** 重點區段在第一屏同時可見；新區段先對照現有元件與路由。
- **Do** 每個動畫尊重 `prefers-reduced-motion`，並先回答「為什麼動」。
- **Do** 淺色與深色都要設計並檢查對比。
- **Do** 毛玻璃一律附 `prefers-reduced-transparency` 純色降級，並實測模糊背景下的文字對比。
- **Do** 載入用貼合版面的骨架、空狀態說明怎麼放第一筆資料；新的選取狀態一律用深銅底加勾，不另創樣式。
- **Do** 所有介面文字使用繁體中文與台灣用語，以 WCAG 2.2 AA 為基準。
- **Do** 換字型或改字型網址前，先重跑字符涵蓋腳本與 `fontStack.test.js`。

### 遊戲專區與測驗（P4，2026-11-18）
- **遊戲入口與個人進度（P4-1）：** 沒有任何伺服器端的遊戲紀錄，所以進度只存在**這台裝置的瀏覽器**（`yy.game.progress.v1`，`src/_game/gameProgress.js`），不上傳、不跟帳號綁定；入口頁一律標明，並提供「清除我的遊戲進度」。記每款遊戲的最高分（發音練習單位是「分」，其餘是 %）、最近玩的族語與日期，以及全部遊戲合起來的有玩日期（算連續天數，今天或昨天有玩才算連續中）。**沒有資料的欄位不顯示**，新使用者看到的是空狀態說明，不是 0。各遊戲結算畫面掛 `GameResultRecorder`（不渲染，只在結算出現時記一筆）。卡片 hover 微傾斜（`useCardTilt`，最大 3 度，只在有滑鼠且沒開減少動態時，直接寫 CSS 變數）。
- **遊戲族語頁（P4-2）：** 粉紅大面板改象牙底；介紹用 `GameIntro` 收成 3 行加「了解更多」（全文仍可讀），開始鈕是主要動作、在第一屏。
- **答對答錯回饋（P4-3，強度 7）：** 答對選項微彈 1.04、勾號再彈一次；答錯水平輕搖一次（左右各 6px、240ms）。只用 transform、各播一次，掛在 `.correct`／`.wrong` 上所以快速換題會被中斷；減少動態下不播，對錯靠 ✓／✗ 與文字（「答錯了，正確答案：…」）。
- **遊戲結算（P4-4）：** 分數環（單一強調色）、與上次比較（同樣只存本機，第一次玩不顯示比較）、錯詞一鍵加入**收藏**。「重點複習」是測驗作答紀錄的複習，資料模型不同、無法共用，所以錯詞進的是單字收藏（與結算卡的愛心同一份）。
- **測驗導覽（P4-5）：** 桌面淺色側欄，選取項銅褐底象牙字加「目前」字樣，沒有紅色三角；手機（≤900px）同一組 button 變頂部頁籤（窄螢幕 2×2，不橫向捲動），選取靠底線。用 `aria-current="page"`。
- **步驟條與等級卡（P4-6、P4-7）：** 步驟條是圓點加連線（完成打勾、連線填色只播一次）；等級卡拿掉推薦圖片，改「推薦」小標籤，圓徽章以單一強調色的深淺表示等級。
- **AI 助手入口（P4-8）：** 玻璃膠囊（`.bot-launcher.yy-glass`）加文字「AI 助手」，開浮卡／彈窗／側欄時淡出並不可點。
- **測驗結果診斷（P4-9）：** 詞綴熟練度改條形圖（`ChartFigure`，資料色 `--yy-data-1`）；數字寫在每一列、另有資料表，不靠長度或顏色。「練這條」會真的回到題目頁，並讓出題 API 的 `focus_rule` 優先安排該詞綴的句子填空題（只影響句子填空；旗標關閉或規則無效時照原本出題）。

### Don't:
- **Don't** 使用硬偏移陰影、貼紙、星芒、膠帶、旋轉裝飾、五色棋盤格。
- **Don't** 在介面文字使用全形或半形破折號當裝飾或分隔（使用者與風格規則）。
- **Don't** 自動播放有聲音的影片（瀏覽器會封鎖，也違反 WCAG 1.4.2）；靜音自動播放必須有可見的暫停與開聲音控制。
- **Don't** 使用外部影音平台或外部上傳服務存放宣傳影片。
- **Don't** 把文化符號、圖騰或族群圖案當成裝飾，除非已經部落、族語老師與行政局確認。
- **Don't** 對族語詞彙使用可能無法正確顯示特殊字母的字型。
- **Don't** 只靠顏色表達對錯或狀態。
- **Don't** 把族語色用在整塊填色或文字色；它只出現在小圓點與細邊。
- **Don't** 在鍵盤快捷鍵、Esc、Tab 這類鍵盤觸發的動作上加進出動畫。
- **Don't** 自創導覽列項目；以現有 `navbar.jsx` 為準。

## 深淺色政策（D7 已決定）
- **預設淺色。** 沒有儲存設定、儲存值損壞或未知時一律淺色；使用者選「跟隨裝置」後才讀取 `prefers-color-scheme`。
- **儲存值只認 `light | dark | system`**（localStorage `yy-theme`），`<html data-theme>` 對應；切換不對整頁做顏色過渡。
- **切換介面：** 導覽列右側的「顯示設定」選單（手機放抽屜），單選群組（淺色、深色、跟隨裝置）。S5-3 已實作：`frontend/src/theme/themeStore.js`（狀態與儲存）、`frontend/hooks/useTheme.js`、`frontend/components/navigation/ThemeSettings.jsx`。**功能旗標 `VITE_ENABLE_DARK_THEME=true` 沒開時**（預設，S10 前）選單不顯示、儲存值被忽略、`<html data-theme>` 一律是 `light`；旗標開了才套用 `dark`／`system`。切換當下 `<html>` 暫時有 `data-theme-switching`（約 50ms），全站過渡關閉，整頁一次換色。
- **防閃白：** `<head>` 內、樣式表之前放一小段同步 script 設定 `data-theme` 與 `color-scheme`。目前 repo 沒有 CSP；日後若加 CSP，改用 nonce、雜湊或外部小檔，不開 `unsafe-inline`。
- **公開深色切換的前置條件（全部完成才開；2026-11-06 批准與 Apple 化改版同步公開，對應階段 7 步驟 7-1）：** 1) 導覽、頁尾、表單、彈窗、影片播放器、焦點狀態都有深色版；2) 前台寫死色碼基線歸零；3) 兩個深色區塊加 `color-scheme: dark`、`index.html` 的 meta 改 `light dark`；4) 圖片、logo、圖表、族色、狀態色在深色底驗證；5) 首頁、辭典、筆記、測驗、登入完成視覺檢查且載入無閃爍。
- **深色閱讀：** 不用純白字、內文字重至少 400、長文行高 1.65 到 1.8；族語字母沿用 tribal 字型 stack，深色下重新檢查組合符號、底線與連結辨識。
